# Web challenge collection v2

The v0.6 Pages edition has **90 missions: 30 per workshop**. It adds 72 missions to the original 18, preserves every released ID and puzzle configuration, and does not change native M1 or native M2 scope. All chapters are freely selectable; there is no timer or forced grind.

## Progression

Six five-level chapters introduce tighter packing and arrival dependencies; circuit branches, fixed relays and decoys; and robot turns, repeat blocks, surveys, detours, conditional corners and reusable paired-camp programs. The final cargo puzzle has twelve supplies and a five-stage dependency chain. Circuit boards grow to 8×8 with five stations; robot maps reach 9×9. Difficulty is authored design, not a measured child assessment or a claim of strict numerical difficulty.

## Content and independent verification

`scripts/build-web-content.cjs` authors 24 new static collections from explicit cargo constraints and robot recipes plus seeded, pruned circuit networks. There is no random generation or remote service during play. The generated data is committed in `storm-content.js`; `--check` reproduces it byte-for-byte. Existing content remains in `storm-levels.js`. Optional hints expose verified complete cargo plans and robot programs only after progressively more specific hints.

Cargo uses an independent breadth-first search over weight, deck size, arrival ordering, incompatible pairs, deadlines and trip budgets, then replays every solution through the runtime rules. Circuits use a separate connectivity traversal and verify rotation reachability, locked pieces, and an unsolved initial board. Robot recipes are executed both by an independent interpreter and by the unchanged reference engine, including the real 24-main / 12-body / 160-expanded-step limits. Valid longer solutions remain accepted; optional compactness targets are feasible, not proven optima. All 30 configurations within each workshop are distinct.

`tests/fixtures/web-v5.json` was captured before editing the expansion. Tests compare all 18 old puzzle configurations and migrate both completed and in-progress states. Save schema 6/content 2 uses `questly-storm-v6`; existing `questly-storm-v5`, `questly-storm-v3` and visual-preference keys are retained. An invalid or future v6/v5 save is preserved and prevents overwriting progress; the UI explicitly explains session-only play. Saves remain browser/origin-local, with no cross-device sync or offline cold-launch cache guarantee.

Browser gates exercise real HTTP files and actual controls, all 90 completions, six chapter filters, next-mission navigation, both languages, responsive layouts, cancellation, migration, reload and whole-browser restart. The historical Python suites use set_content and simulated storage; they are reported separately. Public HTTPS deployment is verified separately from local testing.
